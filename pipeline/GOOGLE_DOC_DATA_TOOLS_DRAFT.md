## 3. SECTION 06.1 — 전처리·검증 규칙

### 붙여넣을 위치

`6.1 전처리·검증 규칙`의 `[여기에 작성]`

### 붙여넣을 내용

국회 Open API에서 받은 회의 메타데이터와 공식 PDF를 원본으로 사용했다. HTML 회의록
뷰어는 응답 형식이 일정하지 않아 운영 원문에서 제외했다. PDF는 GCS에 그대로 보존하고
`pdftotext -raw`로 페이지별 텍스트를 추출했다. 발언은 PDF의 발언자 표시를 기준으로
순서대로 분리했으며, 각 발언에 회의 ID와 PDF 시작·종료 페이지를 함께 저장했다.

문자열은 Unicode NFKC와 공백 규칙으로 통일했다. 같은 `meeting_id`, 페이지 ID, 발언
ID가 중복되지 않는지 확인하고 빈 발언, 존재하지 않는 회의키, 잘못된 페이지 범위를
검사했다. 발언 원문과 검색 청크에는 SHA-256을 저장해 재처리 후 내용이 달라졌는지도
확인할 수 있게 했다.

의원 ID는 공식 의원 코드로 만들었다. 이름과 직위가 공식 명부와 확실히 일치할 때만
발언에 연결하고, 동명이인이나 신원을 확정할 수 없는 경우에는 ID를 비워 두었다. 표결
데이터는 안건별 투표 인원과 찬성·반대·기권 명단 수가 모두 일치할 때만 게시했다.

## 4. SECTION 06.2 — 데이터 모델/ERD

### 붙여넣을 위치

`6.2 데이터 모델/ERD`의 `[데이터 모델 또는 ERD를 붙여 넣기]`

### 붙여넣을 내용

```text
meetings
  ├─ meeting_id → agendas.meeting_id
  ├─ meeting_id → pdf_pages.meeting_id
  └─ meeting_id → utterances.meeting_id
                         │
                         ├─ legislator_id → legislators.legislator_id
                         └─ utterance_id → search_documents.jsonData.primary_utterance_id

legislators
  └─ legislator_id → speaker_identity_map.legislator_id

vote_search_documents
  ├─ jsonData.meeting_id → meetings.meeting_id
  └─ jsonData.legislator_id → legislators.legislator_id
```

주요 테이블은 회의 단위의 `meetings`, PDF 페이지 원문인 `pdf_pages`, 발언자 단위의
`utterances`, 공식 의원 마스터인 `legislators`로 구성했다. Vertex AI Search에는 발언
검색용 `search_documents`와 공식 표결 검색용 `vote_search_documents`를 각각 연결한다.

## 11. SECTION 10.1 — 주요 변경 결정

### 붙여넣을 위치

`10.1 주요 변경 결정`의 `[여기에 작성]`

### 붙여넣을 내용

초기에는 국회 API가 제공한 회의록 링크에서 HTML 본문을 받아 발언을 구조화하려고 했다.
하지만 링크의 파라미터를 변경했을 때 요청한 회의와 다른 내용이 반환될 수 있다는 것을
확인했다. 기존 HTML 파생 데이터는 운영 원문에서 제외하고, 국회가 제공한 공식 PDF만
원본으로 사용하도록 변경했다.

PDF 원본은 GCS에 보존하고 BigQuery에는 페이지 원문과 발언 단위 데이터를 저장했다.
검색용 문서는 원본 발언에서 다시 만들 수 있도록 분리했다. 이후 공식 전자투표 부록에
안건별 찬성·반대·기권 명단이 포함된 것을 확인해 표결 검색문서도 별도로 추가했다. 발언
검색과 공식 표결 검색을 분리해 회의 중 발언을 실제 투표 결과로 잘못 해석하지 않도록
했다.

## 13. SECTION 12.1 — 검증 결론 중 데이터 부분

### 붙여넣을 위치

다른 담당자의 서비스 전체 결론과 합칠 수 있도록 아래 문단만 추가

### 붙여넣을 내용

데이터 영역에서는 공식 회의록 PDF 1,803건과 페이지 105,771건을 회의 메타데이터에 모두
연결했다. 발언 937,825건으로부터 검색문서 952,612건을 생성했으며 원본 발언 누락,
문서 ID 중복, JSON 오류, 청크 복원 오류, PDF 연결 오류는 없었다. 공식 전자투표는 검증된
안건 1,596건에서 의원별 표결 354,391건을 만들었다. 표결 인원수가 맞지 않은 66건은
정확성을 우선해 제외했다. 발언 검색문서와 표결 검색문서의 최종 무결성 검사는 모두
PASS다.

추가 검증으로는 Vertex AI Search에 새 표결 Data Store를 Import한 뒤 실제 의원명·안건명
검색 결과와 PDF 페이지가 일치하는지 확인해야 한다. 신규 회의록이 추가될 때는 증분
수집 후 두 검색 테이블을 다시 생성하고 Data Store를 FULL Import해야 한다.
